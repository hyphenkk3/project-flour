## Storage upload compatibility finding — resolved for observed managed version

Read-only Production Storage logs from 2026-10-17 08:27 UTC through 2026-10-18 08:27 UTC reported only managed Storage API `1.80.2`. Read-only Production database metadata confirmed the `storage.migrations` marker `objects-current-version-index` and the matching `idx_objects_current_version` unique partial index on `(bucket_id, name COLLATE "C") WHERE archived_at IS NULL`.

The isolated rehearsal restored the validated October 17 Production-shaped schema/Storage metadata and ran `public.ecr.aws/supabase/storage-api:v1.80.2` (digest `sha256:95b217a9c59e0ac06c6dcb539df3189a1668a2445fb43dbf29660d6968ffd7d2`) on the internal-only Docker network. Synthetic bucket creation, upload, upsert replacement, read-back, and test cleanup all returned HTTP 200; 42P10 did not occur. One restored historical object read also returned HTTP 200 (2,192,014 bytes). The final isolated counts were 2 buckets and 34 historical objects. The earlier local 34-of-34 read verification remains accepted.

The previously reproduced SQLSTATE 42P10 came from pairing the restored schema with the older local v1.72.1 API, whose unqualified `ON CONFLICT (name, bucket_id)` could not infer the schema's partial/versioned unique indexes. With the managed v1.80.2 image and the recorded migration marker, the API uses `ON CONFLICT (bucket_id, name COLLATE "C") WHERE archived_at IS NULL`, which matches the index. A first historical read in the new local container also had a separate harness-only path error because the restored local file backend omitted `STORAGE_S3_BUCKET=stub`; setting that synthetic namespace made the read pass.

**Decision:** Storage upload/replacement compatibility is **PASS in the matched-version isolated rehearsal**. No application/schema correction or additional migration is justified. This did not issue a Production write. Keep the six-migration allowlist unchanged and re-evaluate only if Production's managed Storage version/schema changes or a new reproducible failure appears.
